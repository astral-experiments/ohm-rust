# What changes

Only `MAX_POOLED_RECORDERS` changes from four to eight in `compiler/rustc_middle/src/dep_graph/edges.rs`. A task still owns its recorder exclusively. The global locked pool contains only finished recorders; this change retains at most four additional entries and does not share a live read set between tasks.

When a task outgrows the unchanged 16-entry inline buffer, it pops a recorder or creates one, clears its read list, advances its epoch, and seeds the existing reads. On epoch wrap, the existing code clears the epoch array. Membership tests, collision handling, growth, first-read ordering, locking and wrap behavior are byte-identical source. The three release contract tests exercise 1,024 reuse cycles with duplicates/order checks, bounded nested retention, and the wrap boundary. Ten existing incremental cases cover 29 actual revisions, with zero failures or ignored cases.

The retained candidate driver's executable section differs at eight immediate bytes, each changing the cap comparison from four to eight. Every other executable-section byte matches. The other differences are the build ID and compiler metadata; all 73 non-driver runtime files, including matching std, are identical. `assembly-change.json` and both runtime manifests identify the actual pair. The separate contract-test overlay was not a performance driver.

This is a bounded allocation-reuse hypothesis. More retained recorders can avoid discarding and recreating dense epoch arrays, at the cost of retained memory. The observed node range fits 524,288 epoch slots and at most that many distinct read indices per recorder. Four additional slots therefore permit 10,485,984 bytes of buffer/header capacity, before allocator overhead. Actual vector capacities were not observed. Larger crates can retain more bytes, and one sampled native high-water observation per arm does not establish a memory improvement.

Cross-arm compiler-context directories are genuinely different. The native preflights preserve equal StableCrateIds, compiler metadata disambiguators and the existing typed directory semantics. The same compiler across the two hosts also changes all 36 workspace public/private hashes. An identical generated serde_core source file has a context-dependent encoded filename and StableSourceFileId, providing a concrete source of propagated hash changes. This is not a full serialized-equivalence proof. Native/profile output bytes must still match exactly within each arm; no general metadata rewrite or new exception is admitted.
